# Trellis 流程轻量化：第二版材料按需

## Goal

在本仓库 Pi 试点中减少任务启动前的材料维护成本，保留已交付的决策生命周期、结构校验和实施批准。用户已评审并批准完整计划，按既有任务规则激活后实施。

## Requirements

- 主线程直接实施时，不为未发生的代理交接提前维护 implement.jsonl / check.jsonl；真实委派前准备所需上下文。
- 任务材料按目标、技术取舍及执行依赖展开，避免为凑齐文件重复记录；lightweight 已可仅有 PRD，不将既有能力当作新增成果。
- 明确目标、范围和验收；重要技术选择及必要执行安排仍须记录，不通过把复杂任务误标为 lightweight 绕过要求。
- 保留决策记录状态、否决理由、适用条件及重议关系；不要求每个任务新增决策。
- 工作流、恢复入口与脚本就绪/结构校验必须一致，不能提示允许缺省而运行时继续阻断。
- 默认继续本仓库 + Pi 试点，不修改本机安装配置、全局目录、其他平台流程或公共推广入口；共享脚本与模板镜像影响在规划中明确，扩大范围须评审确认。
- 不新增流程引擎或任务状态体系；不修改提交、归档及日志策略，不进行历史任务批量迁移。

## Acceptance Criteria

- [ ] 不需要代理交接的 Pi 任务，无须填充仅供代理消费的 JSONL 才能进入实施。
- [ ] 真实代理交接前，所需清单及引用有效；缺失或错误时不以空上下文继续。
- [ ] 精简后的任务材料仍覆盖目标、验收、必要方案与执行安排，缺失必需内容时结构校验继续阻断状态变更。
- [ ] 已有完整三文档任务仍可按原格式使用；不批量删除已有文档或 JSONL。
- [ ] 决策结构及重议关系检查保留；未启用结构校验的项目不受额外要求影响。
- [ ] 方案明确 Pi 试点、共享脚本及模板镜像的边界；不修改仓库外文件，不执行安装、测试、构建、提交或推送。
